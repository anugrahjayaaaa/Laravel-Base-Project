# i18n Architecture — Index

> **Canonical i18n documentation lives in [docs/base/features/i18n.md](base/features/i18n.md).**

This file contains the **decision rules** and **Hermes enforcement rules** that
complement the feature doc. Keep both in sync.

## Quick reference

- **Supported locales**: `en` (canonical), `id`.
- **Translation files**: `lang/{en,id}/{ui,messages,validation}.php`
- **Runtime override**: spatie `language_lines` DB table, seeded by `LanguageLineSeeder`.
- **Helpers**: `ui('key')` → `__('ui.key')` (Blade views); `__('messages.key')` (PHP / API).

## Translation groups (decision tree)

| Group | When to use |
|---|---|
| `ui` | Static interface terminology: labels, headings, buttons, nav, badges, table headers, modal titles |
| `messages` | Contextual feedback: flash, success/error, API JSON `message`, confirmation dialogs, app-specific validation |
| `validation` | Laravel framework validation rule messages |

**`plans.php` was removed** — its keys (`feature_limit_exceeded`, `permission_feature_mismatch`)
were app-specific validation messages → moved to `messages.*`.

Decision tree:
1. Framework validation error? → `validation`
2. Contextual feedback (success/error/confirmation/API)? → `messages`
3. Static UI terminology? → `ui`
4. Genuinely distinct domain namespace? → only if documented in ADR
5. **Otherwise**: do NOT create a new group.

> **DO NOT create a new translation file/group just because a new feature exists.**

## Naming conventions

### DO
- `ui.save`, `ui.cancel`, `ui.email`
- `messages.user_created`, `messages.cannot_lock_self`

### AVOID
- Synonym duplicates: `save_success`, `saved_successfully`, `save_completed`
- Redundant suffixes: `_text`, `_label`, `_message`
- Keys encoding wording: `click_here_to_save`

## Locale consistency

- `en/` is source of truth; `id/` must have every key with matching placeholders.
- Check: `php scripts/i18n_audit.php` (file-level) or `php artisan test --filter=TranslationTest`.

## Security

- Translations = presentation text **only**. Never secrets, tokens, credentials.
- Never use translation values for authorization decisions.
- Dynamic user data → **placeholders**, auto-escaped by Laravel.

## Rules for Hermes

- Inspect existing keys before creating a new one; reuse semantically.
- `ui` for static UI, `messages` for feedback, `validation` for framework rules.
- Do NOT create a new namespace without ADR justification.
- Keep locales structurally consistent; preserve placeholders.
- Do not hardcode user-facing text that should be localized.
- No business logic, authorization, or secrets in translations.
- Follow `docs/base/features/i18n.md` + this doc as source of truth.
