# i18n Architecture — Index

> **Canonical i18n documentation lives in [docs/base/features/i18n.md](base/features/i18n.md).**
> This file contains the **decision rules** and **Hermes enforcement rules** that
> complement the feature doc. Both must be kept in sync.

## Quick reference

- **Supported locales**: `en` (canonical), `id`.
- **Translation files**: `lang/{en,id}/{ui,messages,validation}.php`
- **Runtime override**: spatie `language_lines` DB table, seeded by `LanguageLineSeeder`.
- **Helpers**: `ui('key')` → `__('ui.key')` (Blade views); `__('messages.key')` (PHP / API).

## Translation groups

| Group | Responsibility | Used by |
|---|---|---|
| `ui` | Static interface terminology (labels, headings, buttons, nav, badges, table headers) | Blade views via `ui()` |
| `messages` | Contextual feedback (flash, success/error, API JSON `message`, confirmation dialogs, app-specific validation) | Controllers, API, PHP via `__('messages.*')` |
| `validation` | Laravel framework validation rule messages | Laravel validator (array values skipped in seeder) |

**`plans.php` was removed** — consolidated into `messages.*` because its two keys
(`feature_limit_exceeded`, `permission_feature_mismatch`) were app-specific validation
messages, not UI labels.

## Decision tree (for Hermes)

1. Is it a **framework validation error**? → `validation`
2. Is it **contextual feedback** (success/error/confirmation/notification/API message)? → `messages`
3. Is it **static UI terminology** (button, label, heading, nav, badge)? → `ui`
4. Is it a **genuinely distinct domain namespace**? → only if documented in an ADR (`docs/adr.md`)
5. **Otherwise**: do NOT create a new group.

> **DO NOT create a new translation file/group simply because a new feature exists.**

## Key reuse rule

Before adding a key:
1. Search `lang/en/*.php` and `lang/id/*.php`.
2. Search the codebase for semantically equivalent wording.
3. Reuse an existing key when meaning and context match.
4. If a key is poorly named but equivalent, rename it in one PR and update references —
   don't duplicate.

## Naming conventions

### DO
- `ui.save`, `ui.cancel`, `ui.email`
- `messages.user_created`, `messages.cannot_lock_self`, `messages.confirm_lock`

### AVOID
- Synonym duplicates: `save_success`, `saved_successfully`, `save_completed`
- Redundant suffixes: `_text`, `_label`, `_message`
- Keys that encode wording: `click_here_to_save`
- Keys based on screen location: `delete_button_modal`

## Locale consistency

- `en/` is the source of truth; `id/` must have every key with matching placeholders.
- Automated check: `php scripts/i18n_audit.php` (file-level parity) or
  `php artisan test --filter=TranslationTest` (includes DB override).

## Placeholder rules

- Use `:placeholder` (Laravel native).
- Pass replacements as array: `ui('last_login', ['time' => ..., 'ip' => ...])`.
- Never bake dynamic user content into translation string definitions.

## Security

- Translations are **presentation text only** — never secrets, tokens, or config.
- Never use translation values for authorization decisions.
- Dynamic user data must go through **placeholders** and is auto-escaped by Blade/Laravel.

## Hardcoded strings (classification)

**Must be localized**:
- Flash/success/error messages in controllers → `messages.*`
- UI labels/buttons/placeholders in Blade → `ui('...')`
- API JSON `message` fields → `messages.*`

**Intentionally hardcoded** (technical/structural):
- Activity log `description` values (`'user_locked'`, `'user_unlocked'`) — log identifiers, not displayed directly
- Exception throw messages — developer-facing
- Machine-readable codes — kept separate from localized message text

## API guidance

API responses return localized `message` via `__('messages.*')`. For machine consumers,
return a stable `code` alongside the localized message — but **do not introduce breaking
API changes** unless justified.

## Files changed in this consolidation

- `lang/en/plans.php`, `lang/id/plans.php` → **deleted** (keys moved to `messages`)
- `lang/en/messages.php`, `lang/id/messages.php` → added `feature_limit_exceeded`, `permission_feature_mismatch`
- `app/Http/Requests/Plan/PlanRequest.php` → updated `__('plans.*')` → `__('messages.*')`
- `database/seeders/LanguageLineSeeder.php` → dropped `plans` from seeded groups
- `tests/Feature/TranslationTest.php` → added locale parity + placeholder test

## Rules for Hermes

- Inspect existing translation keys before creating a new one.
- Reuse an existing key whenever semantically appropriate.
- Never create duplicate keys for the same concept.
- Use `ui` for static interface terminology; `messages` for feedback.
- Use `validation` for framework validation messages only.
- Do NOT create a new namespace without documenting an architectural reason (ADR).
- Keep all locales structurally consistent — run the parity test.
- Preserve placeholders across all locales.
- Check for unused/obsolete keys when modifying i18n; document, don't guess.
- Do not hardcode user-facing text that should be localized.
- Do not put business logic, authorization logic, or secrets into translations.
- Follow `docs/i18n.md` + `docs/base/features/i18n.md` as the source of truth.
- When uncertain, inspect existing usage and patterns before introducing a new translation structure.
